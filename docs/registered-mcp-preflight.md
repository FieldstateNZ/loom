# Registered private-memory credential readiness

`POST /admin/tenants/{tenant_id}/mcp-servers/lucidbrain/preflight` is a root-administrator operation. The sole body field is `expected_binding`, containing `principal_id`, `workspace_id`, `agent_definition_id` and `credential_id` UUIDs. Extra fields, including caller-supplied credentials, are refused. The request body is limited to 2 KiB and readiness is bounded to 15 seconds.

The handler uses the same gateway preparation path as a real memory turn: the registered encrypted bearer (or installed private grant), the actual MCP context, stateless transport, authorized tool discovery and a read-only task-category lookup. It checks an active tenant and rejects a changed registration before returning a point-in-time proof. It never substitutes a token supplied by the caller. A private-grant implementation can renew its credential through that existing path; this operation is not a promise of zero database writes.

A successful no-store response has exactly ten fields: `schema_version: 1`, `credential_preflight_version: 1`, `state: ready`, `tenant_id`, `registration_id`, `name: lucidbrain`, `binding`, `allowed_tools`, `category_id` and `transport_mode: stateless`. It contains neither credentials nor private URLs. It creates no conversation, invokes no model and dispatches no task/capture. Non-ready responses must prevent account output and publication; an unsupported older server is not a fallback.

This is readiness at one moment, not continuous revocation monitoring or a lease handed to the phone. Existing per-request authorization and lifecycle controls remain necessary. A separate receipt context can attest account ownership, but it cannot prove the credential actually registered in Loom works; operators need both checks.

Regression tests in `gateway_actions.rs` use actual PostgreSQL and the real admin router. They cover healthy readiness, root-only access, unknown credential fields, invalid registered bearers despite a separate healthy bearer, stateful context, wrong binding, suspended ownership and a registration changed during category discovery. They assert zero inference and task captures. Combined-service qualification belongs to Tandem's account integration helper; it additionally exercises actual expired, revoked and other-owner tokens against production LucidBrain migrations.
